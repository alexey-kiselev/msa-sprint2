# Стратегия миграции данных

## Миграция данных

1. Новые брони сохраняем в booking-service, старые оставляем в монолите.
2. Список бронирований читаем из booking-service, а если нет данных - идём в монолит.
3. После успешного запуска и работы booking-service копируем брони из монолита в микросервис.

## To Be

- Все операции бронирования (создать, получить список и т.д.) работают через микросервис.
- Монолит только проксирует запросы.
- После миграции таблицу бронирований в монолите можно удалять.
